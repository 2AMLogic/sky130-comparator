Generation (regenerates the GDS and every evidence file, ~1 min):

```sh
python3 layout/gen_comparator.py           # regenerate + verify + emit
python3 layout/gen_comparator.py --check   # byte-compare against the committed GDS
```

`--check` passes (re-verified at the 0.7.0 pin, issue #123): the flow is deterministic (no randomness, no dict-ordering
dependence), so a re-run at the pinned toolchain reproduces
`comparator.gds` byte-for-byte. It also survived the klt 0.5.0 → 0.6.0 bump
(#47) unchanged — the committed GDS is byte-identical across both generator
builds, so nothing in that toolchain move is a geometry change.
`compose-report.json` did move: klt 0.6.0 records a `source_path` +
`source_digest` per placed block (additive; no field removed), so the
compose evidence now pins each `klt gen` block's own GDS by hash.

**Toolchain pin.** `klt` (klayout-tools) **0.7.0** on the **klayout
0.30.12** engine (the engine klt 0.7.0 build-tests against,
`klayout_tools.build_identity.klayout_version_expected()`; issue #123 moved
both pins together), the same pin as `docs/environment-setup.md` and
`.github/workflows/t1-signoff.yml`; PDK `sky130A` at open_pdks
`c6d73a35f5…` (`~/.volare`, per `sim/pdk.json`). Override the install root
with `--pdk-root`, and the binary with `--klt` (e.g. a venv that holds the
pin). The engine is pinned because klt declares only `klayout>=0.30` and
stamps `provenance.klayout_version_mismatch` against the version it
build-tests on; see `docs/environment-setup.md` for the measurement behind
that pin.

## Method

Devices are 100 % `klt gen` geometry — `diff_pair` (input pair, steering
pair, latch pairs, reset pair, absorber-cap pair), `mos_array` 1×1 (the two
single tail devices, the clock cap), `res_array` (the load pair, folded
`rows=2`; the shaper resistor). Placement and every wire come from the
repo-controlled router in `gen_comparator.py`, emitted through `klt draw`
and merged by `klt gen-compose` used **as a placer only** — its own routing
is not a signoff path (routed legs land li1/met1 spacing violations and a
block with more than one same-block self-net — which a `splits`-interleaved
pair inherently is — can only get one routed; klayout-tools#1386). The split
is safe because every `klt gen` block draws only nwell/diff/poly/licon1/li1:
met1 and met2 belong entirely to the routing cell, so a route cannot short
into a block; only a deliberately placed `mcon` connects them. Both the
method and the router architecture follow the same-PDK precedent
(`2AMLogic/sky130-sar-adc` `layout/comparator/`), adapted to this design's
16-device DR-004 topology; the generator file name follows the gf180 twin's
convention (`gen_comparator.py`).

Matching priorities, in the order the ratified spec rows track them:

1. **Input pair `M_PINN`/`M_PINP`** (W=13, the offset-critical pair):
   `diff_pair --splits 2` — a common-centroid cross-quad interleave of two
   W=6.5 µm legs per device. A linear process gradient across the pair
   cancels to first order.
2. **`R_LP`/`R_LN`**: the two folded rows of one `res_array` (adjacent
   identical bodies, shared environment). Poly-resistor matching is not an
   `_mm` model term on this PDK — layout proximity is the only place this
   matching is addressed.
3. **Steering/latch/reset pairs**: plain `splits=1` A/B placement at full
   width — symmetric under the OUTP↔OUTN swap, proportionate effort.

Routing symmetry is measured, not asserted (`route-summary.json`): wire-area
imbalance **OUTP/OUTN 3.50 %**, **OUTP1/OUTN1 7.82 %**, **VINP/VINN 13.52 %**
(wire area is a proxy for capacitance; the VINP/VINN residual is structural —
the cross-quad's two input nets must cross, one above the pads and one
below, and cannot share a track).

## Floorplan against the input-node parasitic-capacitance risk

DR-004/DR-005 record the asymmetry this floorplan trades against: layout
capacitance at `VINP`/`VINN` **raises** kickback, and the Kickback row's
margin is thin (1.06–1.13× at the DR-004 anchors; a 1 % stretch-bound
breach at `sf`/−40 °C already recorded), while capacitance at
`OUTP1`/`OUTN1` lowers noise but slows the preamp (Decision-time ratified
≤ 1.5 ns vs 0.5375 ns worst graded corner — margin is large).

The trade taken, and what the post-layout re-verification issue (T1 item 7)
should re-examine:

- **The clock shaper (`R_CLKS`, `M_CLKCAP` W=20) and the two W=40 absorber
  caps sit on the far side of the steering pair from the input pair** — the
  `CLKT` trunk set lives at x ≥ 17.3 µm while `inpair` geometry ends at
  x ≈ 8.6 µm and the VINP/VINN trunks at x ≈ 5.1 µm, so the clock net and
  the three largest devices never cross the input region.
- **Input routes are short and symmetric** — VINP/VINN trunks exist only
  beside `inpair` (4.3 µm² / 3.7 µm² of wire).
- **What pays for it**: the `OUTP1`/`OUTN1` nets run long (from the input
  pair's drains past the loads to the absorber-cap gates ~22 µm away),
  adding preamp-output node capacitance — the axis with margin. The
  measured imbalance between the two halves stays single-digit (7.82 %).

### What the post-layout re-verification measured (issue #57, T1 item 7)

> **Staleness notice (issue #123, 2026-10-09).** Every figure in this
> section was measured against the **0.42 µm-resistor layout extracted under
> klt 0.6.0 / klayout 0.30.10** (17.52 kΩ total series R). The committed layout
> now draws the resistors at 0.35 µm and is extracted under klt 0.7.0 / klayout
> 0.30.12: `klt extract --parasitics` reports **14.769 kΩ** total series R and
> 117.509 fF ground C (was 17.524 kΩ / 117.653 fF). The change decomposes: the
> *old* GDS extracted under klt 0.7.0 gives 14.696 kΩ / 117.653 fF, so the
> toolchain bump alone moved series R by −2.83 kΩ (the extractor's lumped
> supply R, e.g. `VDD` 2357 → 1890 Ω, `VINN` 407 → 219 Ω) and the 0.35 µm
> re-draw added +0.07 kΩ (0.5 %) and −0.14 fF. The per-record post-layout
> numbers below and in `sim/comparator-decision/records/` are therefore
> **historical** and have **not** been re-measured at the new geometry/pin;
> that campaign is tracked as #125 (it is a multi-corner
> Monte Carlo campaign that does not fit this host). Do not read them as
> measurements of the current `layout/comparator.gds`.

The extraction and re-simulation this section anticipated has since run — see
[`sim/comparator-decision/README.md`](../sim/comparator-decision/README.md)'s
"Post-layout records" for the full table and
[`extract_pex.py`](extract_pex.py) for how the extracted DUT is derived.
The trade above is **confirmed, and it cost more on the kickback axis than the
floorplan assumed**:

- **Kickback rose 1.8902 → 2.6767 mV** at `tt`/27 °C (1.42×), clearing the
  ≤ 5 mV target with 1.87× margin but **breaching the ≤ 2 mV stretch figure by
  34 %**. Keeping the clock shaper and the two W=40 caps off the input region
  did not make the input nodes parasitic-free: `klt extract --parasitics`
  reports 117.65 fF of ground capacitance and 17.52 kΩ of series resistance
  across the 12 nets, and the input pair's own routing and star-leg resistance
  are enough to widen the disturbance. This was the predicted direction; the
  magnitude is the new information. (The series-R figure is the extractor's
  coarse single-lumped-star default, dominated by the supply nets and expected
  to be pessimistic there — see the sim README.)
- **The axis "with margin" paid as expected, and then some.** The long
  `OUTP1`/`OUTN1` nets cost 2.12× of pick-off gain (64.4571 → 30.4600 V/V) —
  together with the drawn-vs-schematic load-resistor width delta below — which
  is what pushes decision time 0.4025 → 0.5325 ns (both bounds still cleared),
  offset σ 1.7857 → 2.4446 mV, and input-referred noise 0.5704 → 0.6576 mV rms
  (over the 0.6 mV stretch figure). So the trade landed on the axis it was
  aimed at; that axis simply had less margin against the *stretch* figures than
  against the targets.
- **The 7.82 % `OUTP1`/`OUTN1` wire-area imbalance is not free.** The extracted
  DUT has a **systematic** input-referred offset of 0.6547 mV where the
  symmetric schematic netlist has exactly 0, and the sub-20 mV decision is
  polarity-asymmetric (see the sim README). Wire-area imbalance was committed
  here as a proxy for capacitance imbalance; this is the first measurement of
  what that proxy costs electrically.
- **Measured consequence (issue #66): the imbalance has a decision cost, and
  it is corner-split.** The decision-referred offset bisection
  (`sim/comparator-decision/run.py offset-bisect`) measures the extracted
  DUT's decision flip at **+1.8359 mV** at `tt`/27 °C against the symmetric
  schematic fragment's −0.0391 mV — a **+1.875 mV systematic decision
  offset**, the number the sub-20 mV asymmetry above was bracketing — and
  finds **no decision flip at all** at `ss`/−40 °C, only a 28.2422 mV-wide
  non-decision band [−8.2715, +19.9707] mV where the schematic fragment's
  own band at that corner is symmetric ±0.8203 mV (records
  `sim/comparator-decision/records/20261002-000502-e2b808c.md` …
  `.../20261002-004906-e2b808c.md`). The `tt`/27 °C flip's direction (more
  positive input required for a correct decision) is consistent with the
  extracted DC operating point's `OUTN1` starting above `OUTP1` (1.3172 vs
  1.3147 V), and the 17.2× band widening at the cold corner is consistent
  with the parasitic loading this section documents slowing regeneration —
  **consistent-with, not attributed-to**: separating the routing imbalance
  from the disclosed drawn-vs-schematic load-resistor delta would need a
  counterfactual extraction this pass did not build. The spec consequence is
  proposed in
  [DR-007](../spec/decision-records/DR-007-systematic-decision-offset-row.md).

## Body ties

Drawn ahead of ERC (T1 item 11) because a layout
without them is not what item 4's LVS compares: a p-substrate tap
outside every n-well contacted up to GND, and an n-well tap inside the
merged pfet well contacted up to VDD. They are now also the two `ties[]`
entries `erc-spec.json` declares — see "ERC: supply-spec run, committed"
below, which is where their *connectivity* (rather than their existence) is
verified. `klt extract` over the committed GDS
shows every NMOS body on GND and every PMOS body on VDD as real nets — not
a deck-synthesized proxy, which is why `lvs-report.json` records
`body_verification.status: "verified"` rather than `unverified`. (The first compose attempt had the well tap
straddling the n-well edge — its outside half acted as a substrate tap and
extract reported a single merged `GND|VDD` net; the fix, fully inside the
well, is in the committed geometry.)

## Resistor width: drawn at the schematic's 0.35 µm (issue #123)

The three poly resistors are drawn at the schematic's **0.35 µm** width
(`res_high_po_0p35`), at its lengths (22 µm loads, 1.75 µm shaper). The
extraction deck classifies them `res_high_po` (`w=0.35`), and
`lvs-report.json` compares their L and W against the schematic explicitly (see
the LVS section).

**History (dated, kept as record).** Through klt 0.6.0, `res_array` rejected
`width_um < 0.42`
([klayout-tools#2407](https://github.com/2AMLogic/klayout-tools/issues/2407)),
so until 2026-10-09 the resistors were drawn at that floor, 0.42 µm, ~20 %
wider than the schematic device, and the then-committed LVS `match` was
silent about it at klt's default parameter scope. The per-flavour width floor
(accepting `width_um >= 0.35` for sky130's `high`/`xhigh`) merged upstream as
klayout-tools#2436 and shipped in the published `klayout-tools==0.7.0`.
Issue #123 bumped the pin, regenerated the layout at 0.35 µm, and changed the
LVS request so the geometry is compared. Artifacts that were produced from the
0.42 µm layout (the `sim/comparator-decision/records/` post-layout records)
are historical: they describe the layout and toolchain of their date and are
**not** re-measured here; see "What the post-layout re-verification measured".

Regenerating moved the geometry only where the resistors sit: the GDS is
32156 → 32284 bytes, the composed bbox is unchanged (40.59 × 82.04 µm,
3330.0 µm²), `rclks` shifted 0.035 µm in y, and the `CLK` met1 wire area fell
1.107 → 0.9675 µm² (the narrower `R_CLKS` pad). Composed DRC and
`extract-device-count.json` (16 devices, 9/4/3) are unchanged-clean.

## LVS: run, committed, and cited for T1 item 4 (issue #123)

`klt lvs` runs over the committed GDS, the envelope is committed, and it
reports `status: "match"`. The three resistors are drawn at the schematic's
0.35 µm, and — the part a default-scope match could not establish — the
request forces the resistor class's `L` and `W` into the compare
(`options.compare_parameters: {"res_high_po": ["L", "W"]}`), with the
reference side carrying both: `L` from the call site, `W = 0.35` from the
wrapper mapping (`reference.device_map` `width_um`, klt 0.7.0). Negative
controls (below) show a width or a length disagreement is reported as a
`device.property` mismatch, and that the *default* scope misses even a 10×
width error — which is why the explicit request is part of the claim.

The verdict:

- `engine: "klayout"` — KLayout's native `NetlistComparer` /
  `NetlistSpiceReader`, engine version **0.30.12**, driven by klt **0.7.0**
  (`provenance.klt_version`, `provenance.klayout_version_mismatch: false`).

### Resistor geometry is compared explicitly

KLayout compares only a resistor class's **primary** parameter (`R`) by
default; `L`/`W` are secondary and never take part. Here `R` is excluded as a
placeholder (the reference form is a subckt call), so **at the default scope
the resistors are paired on topology alone** — [klayout-tools#2461](https://github.com/2AMLogic/klayout-tools/issues/2461)
(the report should say this itself). The signoff request therefore asks for
the geometry via `options.compare_parameters`, and klt 0.7.0 lets the
fixed-width wrapper carry its name-baked width (`width_um`, klayout-tools#2459)
so the reference side has a real `W` to compare. This replaces the 0.6.0-era
`__geometry_not_on_card__` placeholder mapping, which made the compare carry
no resistor geometry at all. Standing disclosure: the compare of `R` itself
(value) is still excluded, so resistor *sheet-resistance* is not verified by
LVS, only drawn L and W.

### What the `match` actually covers — `lvs-coverage-probe.json`

An LVS envelope states its verdict, not its reach. `lvs-coverage-probe.json`
is the negative-control matrix `gen_comparator.py` runs beside the signoff
compare (`emit_lvs_coverage_probe`): one extra `klt lvs` run per row against
a **perturbed scratch** request or copy of the reference netlist — the
committed netlist is never written to — each asserting the verdict that
perturbation must produce, with the compared-parameter numbers behind it
recorded in the row's `property_findings`. The generator refuses to commit
anything if a row disagrees. A check that cannot fail grades nothing
(`sim/selftest.sh`'s stage-4 discipline).

| Probe | Perturbation | Verdict | Reads as |
| --- | --- | --- | --- |
| `res_geometry_as_schematic` | none: wrapper `width_um` 0.35 vs drawn 0.35, L/W compared | `match` | positive control |
| `res_width_ref_0p42` | reference `width_um` 0.42 (the old drawn width) | **`mismatch`** | `device.property` `w_um`, layout **0.35** vs reference **0.42** — attribution: the match rests on the geometry agreeing, not on W being unasked |
| `res_width_10x` | reference `width_um` 3.5 | **`mismatch`** | `w_um`, layout 0.35 vs reference 3.5 |
| `res_length_2x` | R_LP L 22 → 44 µm | **`mismatch`** | `l_um`, layout 22 vs reference 44 |
| `res_width_10x_default_scope` | as `res_width_10x`, `compare_parameters` removed | `match` | the default scope misses even a 10× width error; a default-scope match alone would not establish geometry agreement |
| `mos_width` | M_PINN W 13 → 12 µm | `mismatch` | MOSFET width **is** compared |
| `mos_length` | M_PINN L 0.5 → 0.6 µm | `mismatch` | MOSFET length **is** compared |
| `connectivity` | M_RST_N drain OUTN → OUTP | `mismatch` | connectivity **is** compared |

A mismatch row's `property_findings` also record the rows klt lists
*alongside* a mismatched pair to explain it (`as`/`ad`/`ps`/`pd` on a MOS) —
the subckt-call conversion emits only `L`/`W` onto a MOS card, so those read
`0` on the reference side. They are reported for an already-mismatched pair,
not themselves the cause, which is why the clean run carries none of them.
The four warnings the clean run carries (`device.geometry_not_compared`,
`device.parameter_excluded`, `device.placeholder_value`, `topology`) are all
warning-severity and are the disclosures above: `R` excluded by the
placeholder convention and by scope, `A`/`P` secondary, and an empty
reference-side topology note.

### Why item 4 is cited

`manifests/design-evidence-tiers.md` item 4 is "**LVS clean**". Until
issue #123 this layout was not: the resistors were 20 % wider than the
schematic's, and the match held only at a scope that did not look. Now the
drawn resistors equal the schematic's, the request asks for the resistor
geometry, and the negative controls above show the same request reports a
disagreement. The grader's item-4 rule is `status: "match"` and
`power_connectivity != "mismatch"` (here `unchecked`, because a `subckt-call`
reference carries its own supply pins and nets, which take part in the ordinary
compare). The citation pins the layout hash, `klt signoff` re-hashes it
(`input_verified: true`), and the committed `t1-signoff-report.json` records
item 4 `met`.

What the citation does **not** say: resistor sheet resistance/`R` is not
compared (above); `klt lvs` here is one engine (KLayout), not a second
independent one; and the 0.7.0 pairing is with klayout 0.30.12 — the same
request and GDS were also run under klayout 0.30.10 during this change and
returned the same `match` (that run is not committed; it carried
`klayout_version_mismatch: true`).

### Reproducing it

`gen_comparator.py` refreshes the request, the envelope and the coverage
probe with every other deliverable (`emit_lvs_evidence`,
`emit_lvs_coverage_probe`), from the **repo root** against the emitted GDS —
so the envelope records the relative paths `scripts/check-t1-signoff.py`
resolves and the hash a citation would pin. Standalone:

```sh
klt lvs - --format json < layout/lvs-request.json > layout/lvs-report.json
klt lvs --check layout/lvs-report.json          # re-hash the committed report
```

The **stdin** form is load-bearing: relative paths inside a request *file*
resolve against that file's own directory, while the stdin form resolves them
against the current working directory. Run it from the repo root.

That second command is also a CI step (`.github/workflows/t1-signoff.yml`,
job `signoff`), because it closes a rot hole no manifest citation could see:
**a manifest pins an envelope's layout-side hash only.** A change to
`design/comparator.sch` — and so to `design/netlist.sh`'s output, the
compare's *reference* side — would leave this envelope describing a compare
that no longer describes the design (and would silently do so behind a `met`
row, the day item 4 is citable). `klt lvs --check` re-hashes both sides plus
the extraction deck and exits 3 on drift; verified by appending one comment
line to the reference netlist, which flips it to
`[DRIFTED] environment.reference_sha256`. Cheap mode on purpose: `--rerun`
reconstructs the request from the report's own echoed fields, which omit
`reference.form`/`reference.device_map`, so it fails on reconstruction rather
than on real drift (klayout-tools#2459 again).

`lvs-request.json` carries one thing worth explaining. sky130 spells its poly
resistor twice — the geometry-parameterised primitive
`sky130_fd_pr__res_high_po` (`l`/`w` at the call site) and fixed-width
wrappers that bake the width into the *name*
(`sky130_fd_pr__res_high_po_0p35` is literally `x0 r0 r1 sub
sky130_fd_pr__res_high_po l=l w=0.35`). The schematic uses the wrapper; klt's
extraction deck curates only the primitive, so `reference.device_map` binds
one to the other, and `width_um: 0.35` states the width the name bakes in
while `l` stays the call-site parameter (klayout-tools#2459; supported by
klt 0.7.0). Under 0.6.0 the mapping instead pointed `length_param`/`width_param`
at a parameter no call site carries, so the compare carried no resistor
geometry; that placeholder is gone.

### What would strengthen this

Item 4 notes that "a second, independent engine's concurring verdict
strengthens this from 'one toolchain agrees with itself' to a cross-checked
result". `klt lvs` supports `engine: "netgen"`; running it is not attempted
here (netgen is not in this repo's pinned toolchain) and is its own issue.

## ERC: supply-spec run, committed — and why T1 item 11 is claimed (issue #123)

`klt erc` runs over the committed GDS against a committed supply spec, and the
structural supply read comes back **clean**: `erc_status: "clean"`, 0
`erc_findings`, and — the field that matters as much as the verdict —
`erc_coverage.skipped: []`. **`manifests/sky130-comparator.json` cites item 11**
as the compound entry `layout/erc-report.json` + `layout/lvs-report.json`
(the item's two halves). The LVS half is now an honest statement because item
4 is itself supported by explicit resistor geometry; "Why item 11 is cited"
below is the argument, including the weakness that remains.

T1 item 11 is the **structural** supply question only — "is the supply
connected to what it powers". IR drop and electromigration (`klt power`) are
explicitly outside it, and nothing here is a statement about either.

### What the spec declares

`erc-spec.json`, generated by `build_erc_spec`:

- **`stackup`** — the fabrication-order conductor roles the supplies actually
  route on: `poly` 66/20 (`role: "gate"`, with `active_layer` 65/20 so gate
  area is `poly ∩ diff` rather than raw poly-net area), `li1` 67/20, `met1`
  68/20 (`label_layer` 68/5 — met1.pin, where the router writes the seven port
  labels), `met2` 69/20.
- **`vias`** — `licon1` 66/44 (poly↔li1), `mcon` 67/44 (li1↔met1), `via` 68/44
  (met1↔met2).
- **`nets`** — `VDD` and `GND`, both `"kind": "supply"`. This is what makes the
  run mean anything: klt computes `erc.unconnected_net`/`erc.supply_short`
  *only* for declared nets, so a spec declaring no supply reports a clean
  supply for the same reason a rule-free DRC deck reports zero violations.
- **`ties`** — one per well/substrate region, both wired `connect_to: "li1"`
  and both on `tap_layer` 65/44.

**`diff` (65/20) is deliberately not a conductor role.** Registering it would
short every MOS source to its own drain through the channel and collapse VDD
and GND into a single island. That is not an assumption either: the
`supply_short_via_diff` probe row declares it and measures exactly that
`erc.supply_short`.

### The two ties, and why each is expressible the way it is

| Tie | Well declaration | Tap |
| --- | --- | --- |
| `psub_gnd` → `GND` | `well_layer: null` + `well_boxes` — the **native-substrate form** (klayout-tools#2255). sky130 draws no pwell/tub shape for an NMOS-in-bulk block, so there is nothing to name; the spec asserts the region instead: the composed extent (0.00–40.59 × 4.39–86.43 µm) minus the drawn n-well, as four boxes that merge into the one ring-shaped polygon the substrate actually is. | 65/44, `tap_is_dedicated: true` |
| `nwell_vdd` → `VDD` | `well_layer: "64/20"` — the merged n-well is drawn (one polygon, 18.30–25.20 × 28.00–63.00 µm, enclosing both pfet blocks' local wells). | 65/44, `tap_is_dedicated: true` |

Both declarations are held to klt's own falsifiability tests, and both tests
are *exercised against this very spec* by the probe matrix rather than taken on
trust:

- **The tap side** (klayout-tools#2199): a tie whose tap region is "whatever
  that layer draws inside the well" is graded *skipped*, not clean, because an
  ordinary PMOS source contact would satisfy it. `tap_is_dedicated: true` is
  the affirmation that no narrowing is needed — sky130's `tap` is a tap-only
  layer by PDK definition, and **this stream draws 65/44 in exactly two
  places**, the two body-tie structures above (`klt gen` blocks draw only
  nwell/diff/poly/licon1/li1, never tap). `emit_erc_evidence` re-counts 65/44
  against `TAPS` and refuses to commit the envelope if that stops being true,
  so the affirmation is a measured fact. The `degenerate_tap` probe row drops
  it and confirms klt then records `degenerate_tap_declaration`.
- **The well side** (klayout-tools#2255): an asserted substrate region covering
  the whole top-cell extent (to within 1 %) is *skipped*, because "the entire
  die is the substrate" makes `erc.missing_tie` satisfiable by any contact
  anywhere. Subtracting the n-well leaves 241.5 µm² of the 3330.0 µm² extent
  uncovered (7.25 %). The `degenerate_well` probe row widens it back to the
  full extent and confirms klt then records `degenerate_well_assertion`.
- And because the substrate region is *asserted* rather than drawn, the
  envelope says so: `erc_coverage.checked_by_well_assertion` carries
  `erc.missing_tie:["psub_gnd"]`. A `met` item-11 citation would echo that same
  list into its own `power_delivery` block — it is the weaker of klt's two
  narrowing forms and is reported as such. `checked_by_assertion` (the tap-side
  `tap_boxes` form) is empty: no tap geometry was asserted.

### The `erc_coverage` disclosure

Quoted from the committed envelope. Twelve work items **checked**: eight
`erc.floating_gate` (one per discovered gate net), `erc.missing_tie` for
`psub_gnd` and `nwell_vdd`, and `erc.net_connectivity` for `GND` and `VDD`.
`skipped`, `inapplicable` and `unknown` are all **empty**, and
`nothing_checked` is `false`.

`skipped: []` is stated here explicitly, and asserted by the generator,
because it is *not* inferable from the absence of an `erc.missing_tie`
finding: a degenerate tie reports zero findings for a reason that has nothing
to do with taps, and `erc_status` would then read `clean_partial` rather than
`clean`. An item-11 citation built on such a run renders
`supply_spec_incomplete`, never `met`.

### The two documented false-positive caveats, and which narrowing was applied

The item-11 checklist text carries two caveats that must be checked *before* a
supply finding is believed. Neither had to be invoked to explain away a
finding here — the run is clean — but one of them is a narrowing this run
**does** apply, and applying it silently would be exactly the wrong thing:

- **klayout-tools#2183 / #2204 (device bodies read as wires)** — `klt erc`
  traces conductor geometry with no device recognition, so the three drawn poly
  resistor bodies would read as plain poly wires and `VDD` would conduct
  through them into `OUTP1`/`OUTN1`. The run therefore passes **`--deck
  sky130`**, which auto-carves every deck-recognised device body off the
  matching role, and the envelope records what it removed:
  `provenance.devices[]` = one entry, `res_high_po`, `body_layer: "66/20"`,
  `on: "poly"`, `body_area_um2: 19.215`, `source: "deck"`. Without it the
  connectivity graph finds 6 gate nets instead of 8, because VDD, OUTP1 and
  OUTN1 merge across the resistor bodies. No `erc.supply_short` is reported
  either way on this block (the resistors span VDD to a *signal* node, not to
  GND), so the flag buys model correctness rather than a changed verdict — but
  it is applied, it is declared, and it is in the evidence.
- **klayout-tools#2180 (diffusion/well continuity is not modeled)** — the
  mirror caveat, for a supply whose real continuity runs through
  diffusion/well material outside the declared stackup. It does not arise
  here: no `erc.unconnected_net` was reported, and both rails are continuous
  in declared metal (met1 trunks joined by met2 spines), so there is no
  finding for it to explain. `--deck sky130` is the only narrowing applied,
  plus the `tap_is_dedicated` / `well_boxes` declarations above.

### The antenna half, reported but not claimed

The same run also grades antennas (`--pdk sky130`, klt's own limit table — a
table name, not a PDK install): `status: "clean"`, 24 non-gate levels checked,
all `pass`, `coverage.skipped: []`. That is reported for completeness, not
claimed: T1 item 11 deliberately does not grade it (`docs/cli/signoff.md`),
and no T1 item in the vendored checklist is an antenna item.

One detail worth naming so the `gates[]` list is not misread: `gates[]` is
auto-discovered from connectivity (any net with poly-over-diffusion area), and
one of the eight is the net **`VDD`** itself, at 0.4 µm². That is real and
correct — `M_PTAIL` (nfet, W=0.8, L=0.5) has its gate tied to VDD by design,
as the DC tail-bias device (`XM_PTAIL TAILP VDD GND GND …`). Its li1 level
carries the **tightest margin in the whole report** — ratio 63.47 against the
75.0 limit, 85 % of it, where the next-closest graded level sits at 47 % —
because the whole VDD rail's li1 area accumulates onto that one 0.4 µm² gate.
Passing, and the number to watch if the rail ever grows.

### What this check cannot see

`erc.unconnected_net` counts the islands **carrying the declared label**. This
stream draws exactly one met1.pin text per net, so the rule can report zero
islands (nothing carries the name) or — as the `stream_second_vdd_label` probe
row shows by drawing a second `VDD` label in a scratch copy of the GDS — two,
but it can never report a rail physically split into a labelled piece and an
*unlabelled* orphan: the labelled piece still resolves to exactly one island.

`rail_split_no_via` measures both halves of that in one run. It cuts **both**
rails at every met1↔met2 transition, and the envelope reports exactly **one**
finding: `erc.missing_tie` on `VDD`, because the n-well tap ends up on the far
side of a cut from the VDD label. `GND` — equally severed — reports **nothing
at all**, on either rule: its substrate tap happens to stay on the labelled
side, and the orphaned GND pieces carry no label to be counted. So for this
block the "exactly one electrical island per supply" property rests on the
*tie* rule at least as much as on the island rule, and a severed rail whose
tap lands on the labelled side would grade entirely clean. Filed generically
per CLAUDE.md's friction protocol as
[klayout-tools#2497](https://github.com/2AMLogic/klayout-tools/issues/2497)
(the envelope should report the per-net island/label accounting, or the
conductor area unreachable from any label, rather than leaving a reader to
establish the bound by perturbation testing).

### Whether the supply check can fail — `erc-coverage-probe.json`

An ERC envelope states its verdict, not its reach, and for a supply check the
reach *is* the question: every rule here is computed only for what the spec
declares. `erc-coverage-probe.json` is the negative-control matrix
`gen_comparator.py` runs beside the signoff run (`emit_erc_coverage_probe`):
one extra `klt erc` run per row against a **perturbed scratch copy** of the
spec — or, for the last row, of the stream — each asserting the exact set of
`erc_findings` rules *and* the exact set of `erc_coverage.skipped` reasons that
perturbation must produce. Neither committed artifact is ever written to, and
the generator refuses to commit anything if a row disagrees. A check that
cannot fail grades nothing (`sim/selftest.sh`'s stage-4 discipline), which is
the same bar `lvs-coverage-probe.json` already set for item 4.

| Probe | Perturbation | Reports | Reads as |
| --- | --- | --- | --- |
| `tie_wrong_net` | the n-well tie declares `GND` instead of `VDD` | `erc.missing_tie` | the tie check verifies **which** net the tap reaches |
| `tap_boxes_no_geometry` | the substrate tap narrowed to a 1×1 µm region holding no tap | `erc.missing_tie` | a tap assertion matching nothing is an honest "no tap", not a silent pass |
| `psub_split_untapped` | the asserted substrate split into two disjoint bands, only one holding the tap | `erc.missing_tie` | **every** asserted polygon must independently contain a tap that reaches the net |
| `rail_split_no_via` | the met1↔met2 via role removed, cutting both rails at every layer change | `erc.missing_tie` | a severed rail is caught — on the tie rule, because the labelled island survives |
| `supply_short_via_diff` | `diff` 65/20 declared a conductor, so every MOS source reaches its own drain | `erc.supply_short` | the supply-short rule bites, so the committed run's two islands are a measurement |
| `undeclared_supply_name` | a third supply `VPWR`, which nothing labels | `erc.unconnected_net` | a declared supply matching no geometry is reported, not passed vacuously |
| `degenerate_tap` | `tap_is_dedicated` dropped from both ties | *no findings*, `skipped: degenerate_tap_declaration` | #2199's unfalsifiability rejection fires against **this** spec — and would render item 11 `supply_spec_incomplete` |
| `degenerate_well` | the asserted substrate widened to the whole top-cell extent | *no findings*, `skipped: degenerate_well_assertion` | #2255's counterpart rejection, same consequence |
| `stream_second_vdd_label` | a second `VDD` label drawn on met1.pin over the `CLK` label, in a scratch copy of the GDS | `erc.unconnected_net` (2 islands, located) | the multi-island branch bites — and bounds the rule (see "What this check cannot see") |

The last two rows are the ones that make the committed envelope's
`erc_coverage.skipped: []` a *result*. Both grade `clean_partial` with **zero
findings** — precisely the shape a reader would otherwise mistake for a clean
tie check — so the empty `skipped` list on the committed run is the difference
between "the tie check ran and passed" and "the tie declaration could not be
answered".

### Why item 11 is cited

For an `analog` block with no P&R run to cite, `klt signoff` grades item 11 on
two things: this ERC run, and `layout/lvs-report.json` — which must itself pass
(`_check_passed("lvs", …)`) and whose `net_correspondence` must pair every
declared supply to a reference-side net (`_lvs_reference_carries_supplies`).
The grader returns `met` for the compound citation (`erc-coverage-probe.json` →
`signoff_if_cited`: `item_11_status: "met"`; the generator fails if a future klt
changes that).

The earlier decision to withhold item 11 rested on one fact: its LVS half
carries no information beyond "item 4's envelope reports `match`", because
`net_correspondence` lists only matched nets and so tracks the overall
verdict. That measurement still holds (every `lvs-coverage-probe.json` row
records `supply_pairing`: every `match` pairs both supplies; every
`mismatch` drops at least one, including a pure MOSFET-width perturbation).
What changed is the premise that item 4 must not be cited. With the resistors
drawn at the schematic's width and the geometry compared explicitly, item 4's
`match` has nothing known to be wrong behind it, so inheriting it is no longer
over-claiming. The ERC half is independent, falsifiable (nine perturbation rows
each producing the exact finding or skip reason asserted), and clean with no
skipped checks.

Standing limits, stated with the claim:

- Item 11's LVS half is still not an independent supply-continuity
  measurement: it is the item-4 verdict restated. The grader-side weakness is
  [klayout-tools#2495](https://github.com/2AMLogic/klayout-tools/issues/2495)
