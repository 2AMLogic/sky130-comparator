# DR-008: Forward regeneration ladder as a `klt sim` request, not a harness manifest or a `run.py` sub-command

- **Status**: proposed (changes no ratified spec row; see "Spec lines affected")
- **Date**: 2026-10-14
- **Decided by**: builder agent, issue #171 (prerequisite for #170)

## Context

The gf180 twin measures regeneration with a manifest-driven bench
(`sim/comparator-regeneration/testbench/tb.json` + `tb_regeneration.spice`):
a forward overdrive ladder (`td_od50_ns`, `td_od1_ns`, `td_od01_ns`,
`tau_ps`, ...) over a PVT grid. sky130 had none: regeneration is the
Python-generated `run.py regen` sweep (single corner, forward only, no tau,
no polarity proof), and `sim/harness/` only runs `op` analyses
(`testbench._render_body` emits `op`; no `analyses`/`.meas` support). The
twin rule requires identical measure and check names, not identical layout.
Issue #170 (reverse-polarity ladder) needs a forward ladder to mirror.

## Decision

1. The ladder lives in `sim/comparator-regeneration/` as a **`klt sim`
   request** generated by `ladder.py` from `testbench/ladder.json` (measure
   expressions, `.meas` cards, checks) and the existing DUT fragment
   `sim/comparator-decision/testbench/comparator_core.spice` (wrapped in a
   subcircuit so three rungs share one transient, as in gf180).
2. Measure and check names are gf180's forward set verbatim.
3. Grid: one-at-a-time about tt/27C/1.8 V (process x5 @27C, temperature
   x3, supply 1.62/1.8/1.98 V) plus the six other DR-005 graded corners,
   as five requests of <= 5 units executed by `klt sim` (batch fleet on
   dispatch workers). A single 45-unit request timed out on every unit on
   the fleet (see the first record's "Fleet submit"), hence the split. Per-point limits are
   `klt sim` limits; the per-axis spread floors `klt sim` cannot express are
   graded by `ladder.py grade`.
4. Controls: positive = synthetic and live all-pass; negative =
   `--sabotage-polarity` (stimulus signs swapped, polarity checks must fail),
   `grade --expect-fail`, and a flat-corner response that the process-axis
   spread floor must reject.
5. `run.py regen`, the op-only harness, and every existing record are
   untouched.

## Alternatives considered

- **Adopt the gf180 manifest in `sim/harness/`** — needs transient analysis,
  `.meas` parsing, `.param` injection and a per-point runner in the harness
  (~the whole of `testbench.py`/`runner.py`), and its runner calls ngspice
  directly, so a 45-point grid would be hand-launched ngspice on a shared
  host. Rejected: large, duplicates `klt sim`.
- **Add a `ladder` sub-command to `run.py`** — `run.py` drives ngspice
  directly (see `sim/comparator-decision/README.md` "Dispatch decision
  (issue #64)"); a PVT grid there is either serial or hand-parallel.
  Rejected for the same reason; also 4300 lines already.
- **Use the name `tb.json`** — `sim/harness` globs `*/testbench/tb.json` as
  op experiments and would try to run it. `ladder.json` avoids that.

## Spec lines affected

None. These are measurement-sanity checks and a corner-sensitivity anchor,
not a verdict against the ratified Decision-time row (DR-002).

## Consequences

- Deviation from gf180 (thresholds, not names): `dout_*` is the differential
  output normalised as `0.5 + (v(outp)-v(outn))/(2 VDD)`, and this DUT's
  losing output does not reach the rail inside the strobe at the small
  rungs (measured 0.88/0.12 at tt/27C/1.8V), so the polarity checks use the
  decision threshold itself (`>= 0.75` / `<= 0.25`, i.e.
  `|diff| >= 0.5 VDD`) rather than gf180's 0.9/0.1. Delays cross 0.75
  (`rise`, not gf180's SR-latch `0.5`); the energy window is read at 48 ns
  because the outputs reset at 50 ns.
- `klt sim` cannot evaluate spread floors; `ladder.py grade` does, so a
  response must be graded offline as well as by `klt sim`.
- #170 adds mirrored rungs by extending `build_netlist`/`ladder.json`.
